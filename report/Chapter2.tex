\section{The Dataset}
\label{sec:dataset}

The experiments in this project use the NERMuD 2023 dataset, developed as part of the EVALITA 2023 evaluation campaign for Italian Natural Language Processing (available on \href{https://huggingface.co/datasets/evalitahf/entity_recognition}{Hugging Face}). As introduced in Section~\ref{subsec:nermud}, the dataset covers three entity categories: persons, organizations, and locations \cite{palmeroaprosio2023nermud}.

The dataset contains documents from three domains: Wikinews (WN), fiction (FIC), and writings and speeches by Alcide De Gasperi (ADG). Wikinews contains journalistic texts, fiction consists of excerpts from Italian literary works, and the ADG domain contains political writings and speeches. These domains differ in writing style and context, which is relevant to NER because the frequency, distribution, and context of named entities may vary between them.

\subsection{Dataset Organization}
\label{subsec:data-org}

The dataset is organized into multiple JSONL files according to domain and purpose. Each domain is divided into training, development, and test subsets. In this project, the corresponding subsets from the three domains are combined to create a single training set, a single development set, and a single test set, while retaining domain information for later analysis.

Table~\ref{tab:dataset-splits} presents the number of examples in each subset. The training set is used to fine-tune the models, while the development set is used to monitor their performance during training and select the best model checkpoint. The test set is reserved for the final evaluation, allowing the performance of both models to be compared on data that was not used for training or model selection.

\subsection{Entity Categories and Annotation Scheme}
\label{subsec:ent-cat}

The dataset contains three named entity categories: persons (PER), organizations (ORG), and locations (LOC), identifying people, institutions or other organizations, and geographical places, respectively.

The original annotations follow the Inside-Outside-Beginning (IOB) tagging scheme, commonly referred to as BIO. Each token receives a label indicating whether it belongs to a named entity and, if so, whether it begins the entity or continues it:

\begin{itemize}
\item \texttt{B-PER}, \texttt{B-ORG}, and \texttt{B-LOC}: the first token of a person, organization, or location entity.
\item \texttt{I-PER}, \texttt{I-ORG}, and \texttt{I-LOC}: subsequent tokens belonging to the corresponding entity.
\item \texttt{O}: a token that does not belong to any named entity.
\end{itemize}

For example, the sentence ``Umberto Guidoni visited Rome'' is annotated as shown in Table~\ref{tab:bio-example}. This representation allows the models to perform token-level classification while preserving information about the boundaries and categories of named entities.

\section{Data Preprocessing}
\label{sec:preprocessing}

Before training, the dataset is processed so that the text and its annotations can be converted into token-level labels. Each original entry contains the text and a list of annotated entities, represented by their text and entity type. For example, the following entry identifies \textit{Trentino} as a location (\texttt{LOC}):

\begin{verbatim}
{"text": "Nel nostro Trentino attraversiamo un momento storico importante.
", "entities": [{"entity_text": "Trentino", "type": "LOC"}]}
\end{verbatim}

The annotations are then converted into a consistent representation containing the text tokens, their BIO labels, and the corresponding domain. For the example above, the resulting representation is:

\begin{verbatim}
{"tokens": ["Nel", "nostro", "Trentino", "attraversiamo", "un", "momento",
"storico", "importante", "."], "labels": ["O", "O", "B-LOC", "O", "O",
"O", "O", "O", "O"], "domain": "adg"}
\end{verbatim}

The preprocessing procedure includes tokenizing the text, locating the annotated entities, and assigning the appropriate BIO labels to the corresponding tokens. For multi-word entities, the first token receives a beginning label and the remaining tokens receive continuation labels.

Whitespace and punctuation differences can make it difficult to match annotated entity strings exactly to their occurrences in the original text. To address these cases, normalized matching is used as a fallback when an exact match cannot be found, aligning the annotations without modifying the original text.
